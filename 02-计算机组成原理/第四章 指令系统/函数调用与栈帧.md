## 本页约定
采用32位x86、近调用、4字节栈操作、cdecl式栈传参、保留EBP帧指针的教学模型。不同ABI、优化选项及64位模式的布局不同。

CALL把**下一条指令地址**保存到栈中并转移，RET从栈取回返回地址。CALL并不自动建立完整C语言栈帧，函数序言与编译器约定另行完成。

## 典型函数
```asm
; int add(int x,int y)，返回到EAX
add_fn:
push ebp
mov ebp,esp
mov eax,DWORD PTR [ebp+8]   ; x
add eax,DWORD PTR [ebp+12]  ; y
leave
ret
```

原图06反过来先取y、再加x，因为加法交换律仍得到相同结果；若换成减法，参数顺序就不能互换。

建立帧指针后：
```text
高地址
[EBP+12]   第二参数y
[EBP+8]    第一参数x
[EBP+4]    返回地址
[EBP]      保存的旧EBP
[EBP-4]    可能的局部变量/临时空间
低地址
```

具体局部变量并不保证按声明顺序、每个相邻4字节，也可能放在寄存器或被优化掉。

## 建立与撤销
常见序言为`push ebp;mov ebp,esp;sub esp,N`。
常见尾声`leave`在本模型中相当于`mov esp,ebp;pop ebp`，随后`ret`返回。

原图17把前两条直接等同无参数ENTER不准确。`enter N,0`可建立并分配N字节的简单帧；ENTER还包含嵌套级别参数，不能省略条件。

## 参数传递与清理
补充例：`push 80;push 125;call add_fn;add esp,8`，在此cdecl约定下右到左压参，返回EAX=205；调用者归还参数占用空间。

返回整数常在EAX，但结构体、浮点等可能采用其他约定。参数也可能由寄存器传递。

## 纠正绝对说法
- GCC不保证每个栈帧大小固定为16 B整数倍：对齐通常约束特定时刻的栈指针，受ABI及选项影响。
- 旧EBP槽不是每个函数都必有，编译器可以省略帧指针。
- 返回地址在本近CALL模型中保存在栈中，但不能推广为“除main外所有函数一定以相同栈布局调用”。main也可能由运行库调用。
- 调用者保存与被调用者保存的寄存器由ABI规定，不是全部寄存器都由调用者无条件压栈。
